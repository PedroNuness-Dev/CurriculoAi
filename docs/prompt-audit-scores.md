# Manual scores for the live local API baseline

Each input and extracted PDF text is in `backend-spring/target/prompt-audit/live-suite-baseline/<case>/`. The 15 PDFs came from the original localhost server using fictional accounts. The audited branch was tested with a fixture provider for all 15 cases and through an isolated local API with a dummy provider key for the sparse case. The fixture outputs are **not** scored as model performance.

Scores are 1–5 in this order: **F** factual fidelity; **C** completeness; **W** clarity and writing; **ATS** structure and keywords; **Fmt** formatting; **L** language; **R** robustness. The mean is the arithmetic mean of the seven dimensions. ATS 4 denotes standard headings with a project-only structure; Fmt 4 denotes a readable PDF with minor layout or extraction issues. Language 5 denotes fluent Brazilian Portuguese; the baseline API could not request English output.

**Baseline mean: 3.26/5 across 15 PDFs.** The baseline fails zero-hallucination, the ≥4 mean, and the minimum-per-case ≥3 criteria. The audited branch's only live end-to-end score is 4.71/5 for the sparse case. The other fourteen audited means are intentionally blank because the model path was not run with a live provider key under the no-secrets constraint.

Technical observations: all 15 baseline calls eventually returned parseable PDFs after spacing retries around HTTP 429. The public API returned PDFs only, so raw provider text and internal parse failures were not exposed. The 15 fixture-provider outputs in `target/prompt-audit/fixture/` all parsed and rendered, and explicit malformed, truncated, wrong-name, invented-link, and invented-percentage responses were rejected by tests.
